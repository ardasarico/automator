# Automator UI and UX review — 2026-09-08

> **Status:** closed. All ten findings were addressed — the first pass in `3ce7d32`, the rest absorbed by the workspace redesign (`fa4b909`…`2a57df4`) planned in `docs/plans/2026-09-09-workspace-redesign.md`. Kept as the review that motivated that redesign.

## Scope and method

A design-level review of `apps/web`: the workspace shell, Flows, Runs, Data, Marketplace, Wallet, and the flow builder. Complements the correctness audit in `docs/audits/2026-09-08.md`, which covered defects rather than interface quality.

Rendered observations come from the running dev server (Chrome, light and dark, 2560 px viewport, keyboard tabbing). Source observations are cited as `file:line`. Narrow-viewport behaviour was inspected in the stylesheets only; the window would not resize below the browser minimum, and `docs/web-ui.md` already records mobile as out of scope for this milestone.

## What is already strong

Worth naming so it does not get refactored away:

- **Token system.** `packages/tailwind-config/colors.css` carries contrast reasoning in comments (`--accent`, `--destructive` in dark), a full dark palette, and semantic surface/foreground pairs. `--muted-foreground` on `--background` is roughly 7.9:1.
- **Focus and keyboard.** Every interactive element tested showed a visible `focus-visible` ring; icon buttons carry `aria-label`; the shell has a skip link; panels restore focus to their opener (`left-panel.tsx:74`).
- **Motion discipline.** `prefers-reduced-motion` blocks in every stylesheet, `MotionConfig reducedMotion="user"`, no `transition: all` anywhere in the app.
- **Empty states.** Flows, Runs and Wallet each have a written empty state with an illustration, an explanation and a next action — including the harder cases ("No older runs", filtered-to-one-flow).
- **Copy.** Curly quotes, error messages that name the fix, `Intl` formatters for dates and counts. `login-form.tsx` in particular is careful work.
- **Container queries.** `flows.module.css` responds to its container, not the window, so the grid reflows correctly when the sidebar collapses.

## Findings

Ordered by how much the interface improves per unit of work.

### 1. Flow cards are mostly empty space

`apps/web/src/app/(workspace)/flows/flows.module.css:135` fixes the grid at three columns, and `:152` gives each card a `16/10` preview. At the 1440 px page cap that is a ~460 px card with roughly **300 px of placeholder** holding one generic `RiFlowChart` glyph — identical on every card. Two thirds of the page is a repeated icon. In dark mode the preview background and the card background are near-identical and the dot grid vanishes, so the card reads as a void.

The metadata that would actually help — is this flow live, when did it last run, did it pass — is absent. Trigger kind, node count and a date are the weakest three facts available.

Options, cheapest first:

- Drop `.flowPreview` and make the card a dense info card: name, live/draft state, last run status and time, trigger, node count. Four columns then fit at 1440 px.
- Keep a preview but render the real graph — a static mini-layout from `layoutFlowPositions` — so cards are distinguishable at a glance.

Either way, add a fourth column above ~1180 px of container width.

### 2. Every node-palette description is truncated

`flow-builder.module.css:463` sets `white-space: nowrap; text-overflow: ellipsis` at 12 px inside a 142 px box (panel is 260 px, `:221`). Measured in the browser, **all eight category descriptions overflow** (151–230 px needed against 142 px available):

```
"Branch, loop, wait, and shape data."      199px → 142px
"Store and look up records in your tables" 230px → 142px
"Read and write contracts, move tokens."   224px → 142px
"What the visitor sees in the mini-app."   211px → 142px
"Messages to chats and inboxes."           182px → 142px
"Proof of personhood and World ID."        197px → 142px
"Wallets, login, and signing."             151px → 142px
"Payments, payouts, and balances."         193px → 142px
```

The same rule applies to the 38 node descriptions at `node-palette.tsx:60`. So the panel spends a line per row on text that is never readable. Fix: `white-space: normal` with `-webkit-line-clamp: 2` — two lines fit the existing row rhythm and every string above lands inside 2×142 px.

### 3. The Runs table inherits styling tuned for Flows

`run-history.tsx:7` imports `flows.module.css`, which sets `.table tbody th { min-width: 320px; width: 60% }` (`flows.module.css:236`). The Flows table has two content columns and wants that; the Runs table has five, so the flow name takes 60% and Status, Trigger, Started and Duration crush into the right third with a wide dead gap between them. Give Runs its own stylesheet, or scope the 60% rule to the Flows table.

Also on this page:

- **No sticky header.** 25 rows exceed the viewport and the column labels scroll away.
- **No status filter.** The flow `<Select>` is the only control. "Show me what failed" is the first question a runs page has to answer, and it cannot.
- **Failures give no reason in the list.** A `Failed` badge and nothing else; the cause requires opening the run. The failing node's name in the row would remove that click from the most important row type.
- **`0.0s` on waiting runs.** `flowRunSummarySchema` requires `finishedAt` (`packages/contracts/src/flow-runs.ts:84`), so a `waiting` run reports a duration equal to its start and `formatDuration` prints `0.0s` (`run-history.tsx:84`). Show `—` for waiting runs, and `<0.1s` rather than `0.0s` for genuinely instant ones.
- **Pagination is forward-only.** "View older runs" walks the cursor forward; the only way back is a jump to the latest page.

### 4. Onchain node forms give no guidance at all

`components/schema-form/fields.tsx:43` derives every label as `humanize(name)` and ignores `title`, and `packages/contracts/src/onchain-configs.ts` sets no `description` on any property. The result on the nodes that move real money:

| Rendered                | Should be                                                |
| ----------------------- | -------------------------------------------------------- |
| `Abi`                   | `ABI` — plus "Paste the contract ABI as a JSON array."   |
| `Args`                  | `Arguments` — plus the expected JSON shape, default `[]` |
| `Value`                 | `Value` — **no unit stated anywhere**: wei or ETH?       |
| `Function Name`         | fine, but no hint that it must match the ABI             |
| `Table Id` (data nodes) | `Table`                                                  |

The data nodes (`data-node-configs.ts`) show the pattern done right — every field has a `description` and the form renders it. Two changes close this: honour `property.title` in `fields.tsx` before falling back to `humanize`, then add `title`/`description` to the onchain, AI and notification schemas. This is the highest-value copy work in the product, because these are the fields where a mistake costs funds.

### 5. Flow problems are hard to see and harder to read

- The `!` badge on a node uses a native `title` attribute (`flow-node.tsx:66`) — ~1 s hover delay, unstyled, unreachable by keyboard or touch, while every other hint in the app uses the Coss `Tooltip`. Hovering it in the browser produced nothing within two seconds.
- There is **no flow-wide problem list**. With five problems the header shows only the first message (`canvas-header.tsx:39`).
- Simulate has a hidden two-click gate (`canvas-header.tsx:25-33`): with errors present, the first click does not run — it sets `warned` and prints a message. Nothing on the button says it will refuse. And `warned` is never cleared when the problems change, so a much later click runs immediately.

Better shape: a persistent `2 problems` chip in the canvas header that opens a list, each entry selecting its node. Then Simulate can just run, with the chip carrying the risk.

### 6. Live mode is invisible once you look away from the button

The earlier audit fixed the label (`Simulate` → `Run live`). The mode itself is still only knowable from that one word:

- The toggle lives inside the Flow settings dialog (`flow-settings-dialog.tsx:229`) — three clicks from the canvas.
- `liveMode` is `useState(false)` (`flow-activation.tsx:30`), so it silently resets on every reload. A user who set live mode, reloaded, and pressed the button gets a simulation instead — or, worse, builds the opposite habit.
- Nothing else on the canvas changes: same header, same node chrome, same canvas colour.

For a product that signs transactions, the mode belongs in the header as a visible two-state control with its own colour, and the first live run of a session deserves a confirmation naming the chain and the wallet.

### 7. Wallet balances print raw floats

`app/(workspace)/wallet/page.tsx:108` renders the API string directly: **`0.062999769144958985 ETH`**. Format with `Intl.NumberFormat` to ~6 fractional digits, keep the exact value in a `title`, and set `font-variant-numeric: tabular-nums` so the two chain cards align. The page already imports `Intl` formatters elsewhere, so this is an oversight rather than a gap.

### 8. Six keyboard shortcuts exist and nothing mentions any of them

`use-canvas-hotkeys.ts` and `command-menu.tsx` register ⌘K, ⌘Z, ⇧⌘Z, ⌘S, ⌘⏎ and ⌘D. A repo-wide search for a shortcut hint in the UI returns nothing. For a product positioning itself on developer experience this is free polish: append the combo to the Save, Simulate and Undo tooltips, and put a `⌘K` affordance in the canvas header or the node search field.

Related: **undo and redo have no buttons at all.** They exist only as keystrokes and, indirectly, the History panel. A mouse user working on a canvas cannot undo.

### 9. The only action on a flow card is Delete

`flow-browser.tsx` reveals a single trash button on hover or focus. Hover therefore surfaces exactly one thing, and it is the destructive one. Rename in particular requires opening the flow and then the settings dialog. Replace with a `…` menu: Rename, Duplicate, Share as mini-app, Open latest run, Delete.

### 10. Marketplace stacks three filters and remembers none

The page carries a segmented control (All / By Automator / Community / Yours), a category chip row, and a sort menu — three rows of chrome above the cards, with weak visual distinction between the first two. None of it is in the URL, so a filtered view cannot be linked, bookmarked or restored on back-navigation. `run-history.tsx` already does URL state correctly; the same approach applies here.

`ListingMarks` (`marketplace/listing-marks.tsx`) renders a strip of 28 px grey glyphs. They are labelled for assistive tech, but for a sighted browser they are decoration — the row cannot be read. The buying signal is "does this touch the services I use", so show one or two named chips (`Discord`, `USDC`, `World ID`) and a `+2` overflow.

## Smaller items

- **No `<meta name="theme-color">`** (`app/layout.tsx`). Mobile browser chrome will not match the page in either theme.
- **Page headings are quiet.** Every workspace `h1` is `text-section` (18 px, `workspace-breadcrumbs.tsx`). The 30 px `--text-page` token is defined and used on exactly one screen — `app/error.tsx`. Consistent and defensible as a Linear-style choice, but worth deciding deliberately rather than by omission.
- **Two Saves in the builder.** `Save node` in the node-settings header and `Save` in the canvas header. Neither says what the other does not.
- **`Dat…` breadcrumb.** The node-settings header truncates `Data · Find records` to an unreadable stub inside a 260 px panel (`node-settings.tsx:86`).
- **The AI panel is mostly empty.** A 360 px column holding two lines of placeholder text and a composer. It could carry recent prompts, suggested edits or the last proposal instead of white space.
- **Mixed control vocabulary.** Flows sorts with a `Menu`, Runs filters with a `Select`, Marketplace filters with chips. Three interactions for one job.
- **Placeholders.** `Search flows…` is right; the AI composer's example prompt runs two lines and does not end in an ellipsis.

## Known and out of scope

Recorded in `docs/web-ui.md`, not re-reported as defects:

- The workspace shell has no narrow-viewport mode; mobile is out of scope for this milestone.
- The builder is deliberately reduced pending a visual redo, so its missing breadcrumb and draft badge are known.
