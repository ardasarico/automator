## Follow-up fixes

Continued with GPT-6 Astra / medium subagents at the user's request.

- **Polling fencing:** executable edits and activation changes advance an opaque revision, including ABA changes. Scheduler admission checks the revision; row-locked event/watch writes reject obsolete polls, watch observations compare-and-swap, and event cursors cannot regress. Cosmetic edits preserve polling state. Calls already admitted cannot be undone by a later edit.
- **Exact signer authorization:** API wallet metadata must identify the expected wallet and contain the configured `PRIVY_SIGNER_ID` in `additional_signers`. The signing button verifies through the API and refreshes on focus. A broad delegation flag is no longer sufficient.
- **History navigation:** cancelable same-document browser Back/Forward uses the existing leave dialog and resumes the original history entry by key. Repeated Stay preserves history entries and Next.js metadata. Older browsers and noncancelable traversals retain the documented platform limitation.
- **Compact editing:** below 1024 px, both rails remain visible and one panel overlays the usable canvas at a time. Toolbar wrapping, close/Escape focus return, preview and run details work at 390 px. Desktop 260/360 px panel widths are unchanged.
- **Engine limits:** canonical ABI signatures disambiguate equal-arity overloads, including tuples. Nested loops share a default 10,000-node-start budget per invocation. Agent nodes permit 100 cumulative tool calls; HTTP tool output reads at most 16,000 bytes and retains at most 4,000 characters, cancelling the remainder.
- **Secure preview:** the captured document travels only between the exact builder/runtime windows after origin, nonce and flow checks. URLs carry no document or literal credentials. Builder-scoped ownership preserves delivery/reload after hiding the preview pane. Real integration behavior remains intact. Copied preview links cannot retrieve the snapshot; published mini-app links remain shareable.
- **Durable execution:** migration `0012_durable_trigger_claims`, atomic admission/crossing persistence and owner-only issue inspection are wired into API startup and the scheduler. Unresolved executions block other polling-trigger executions across the entire flow, including other instances, without expiry-based takeover. Completed events are deduplicated across cursor-write failures and restarts; schedule intervals consult both ordinary history and the ledger. History failures retain completed evidence independently. Matching unresolved occurrences are blocked rather than marked consumed, preserving the event cursor.

## Payment limits

Implemented at the user's request, without human approvals. Wallet now manages an optional recipient allowlist and exact per-transfer/per-UTC-day native ETH or USDC limits per registry chain. Saving applies immediately to the account's flows. The API signer checks current settings before every operation; unsupported contract calls, message signing and offline transaction signing are blocked while enabled.

Migration `0013_payment_policies` stores settings and permanent payment reservations. Owner-row locking serializes policy edits and admission across workers, preventing concurrent payments from exceeding the configured total. Failed or uncertain submission remains charged; editing, disabling and re-enabling settings never clears that usage. Missing settings default to disabled; corrupt settings fail closed. The measured amount is the direct Automator payment, excluding gas, activity outside Automator, recipient-contract effects and pre-existing allowances. Enforcement lives in Automator's API rather than a Privy platform policy.

## Remaining scope and verification limits

1. **World person uniqueness:** session proof binding is separate from one-person-one-action limits. No global nullifier uniqueness policy is imposed; repeat-use eligibility remains a product decision.
2. **Oracle/finality policy:** maximum feed age, chain confirmation depth and reorg recovery remain policy work; live feed credentials/RPC behavior were not exercised.
3. **Verification limits:** generated-flow loops and real external steps are explicitly skipped by automatic verification. A process lost or submission cancelled before a provider returns its transaction hash still requires external reconciliation. Durable admission blocks automatic replay, but cannot invent an unreturned hash or recover all intermediate outputs. Webhooks have no caller-supplied idempotency key and keep existing request semantics. Real Privy/World ceremonies, signing and physical QR scanning remain untested.
4. **Browser history support:** platforms without the Navigation API, and browser-imposed noncancelable traversals, cannot show the custom same-document leave guard. Cross-document exits retain native beforeunload protection.

## Feature ideas

These are proposals, not implemented features. Priority follows the existing create → test → share → inspect product path.

1. **Saved acceptance scenarios:** keep sample inputs and expected node outputs with the flow; rerun them after edits, including bounded loop assertions. This makes changes to conditions and app screens reviewable beyond a single successful sample run.
2. **Live execution timeline:** stream node progress to the canvas, retain each loop iteration and its effect evidence, and link failures to the executed snapshot. The current API returns the finished run and body-node results generally show the last iteration.
3. **Trigger health and reconciliation:** show last poll/value, data age, cursor and next due run; inspect provider receipts before offering recovery for unresolved effects. The current issue view exposes retained records without an unsafe retry/takeover action.
4. **Publication comparison:** compare the draft with the published snapshot and show relevant scenario results before replacing the shared app.
