## Follow-up fixes

Continued with GPT-6 Astra / medium subagents at the user's request.

- **Polling fencing:** executable edits and activation changes advance an opaque revision, including ABA changes. Scheduler admission checks the revision; row-locked event/watch writes reject obsolete polls, watch observations compare-and-swap, and event cursors cannot regress. Cosmetic edits preserve polling state. Calls already admitted cannot be undone by a later edit.
- **Exact signer authorization:** API wallet metadata must identify the expected wallet and contain the configured `PRIVY_SIGNER_ID` in `additional_signers`. The signing button verifies through the API and refreshes on focus. A broad delegation flag is no longer sufficient.
- **History navigation:** cancelable same-document browser Back/Forward uses the existing leave dialog and resumes the original history entry by key. Repeated Stay preserves history entries and Next.js metadata. Older browsers and noncancelable traversals retain the documented platform limitation.
- **Compact editing:** below 1024 px, both rails remain visible and one panel overlays the usable canvas at a time. Toolbar wrapping, close/Escape focus return, preview and run details work at 390 px. Desktop 260/360 px panel widths are unchanged.
- **Engine limits:** canonical ABI signatures disambiguate equal-arity overloads, including tuples. Nested loops share a default 10,000-node-start budget per invocation. Agent nodes permit 100 cumulative tool calls; HTTP tool output reads at most 16,000 bytes and retains at most 4,000 characters, cancelling the remainder.
- **Secure preview draft:** the captured document travels only between the exact builder/runtime windows after origin, nonce and flow checks. URLs carry no document or literal credentials. Builder-scoped ownership preserves delivery/reload after hiding the preview pane. Real integration behavior remains intact. The loss of independent copied-link sharing is still awaiting the user's answer.
- **Durable execution preparation:** migration `0012_durable_trigger_claims`, the ledger, atomic watch crossing claims, optional execution evidence checkpoints and owner-only issue inspection are implemented. Read-only issue inspection is wired into API startup. Mandatory scheduler claims remain unwired while the crash-retry policy is pending; this preparation does not yet close cross-process duplication.

## Remaining limitations and decisions

1. **Crash-retry policy — answer pending:** decide whether an uncertain automatic run should block further execution for review, or retry with possible duplicate external effects. Ledger admission is not activated until this choice is made. The current scheduler still lacks cross-process/crash deduplication; the scaffold does not claim exactly-once delivery or webhook deduplication.
2. **Preview sharing — answer pending:** the local handoff draft supports reopening/reloading the same popup while the builder remains open. A copied preview link cannot recover its in-memory snapshot. Independent sharing would require a secure server session design. Published mini-app links are separate.
3. **World person uniqueness:** session proof binding is separate from one-person-one-action limits. No global nullifier uniqueness policy is imposed; repeat-use eligibility remains a product decision.
4. **Oracle/finality policy:** maximum feed age, chain confirmation depth and reorg recovery remain policy work; live feed credentials/RPC behavior were not exercised.
5. **Verification limits:** generated-flow loops and real external steps are explicitly skipped by automatic verification. Submission cancelled before a transaction hash returns still requires later reconciliation. Real Privy/World ceremonies, signing and physical QR scanning remain untested.
6. **Browser history support:** platforms without the Navigation API, and browser-imposed noncancelable traversals, cannot show the custom same-document leave guard. Cross-document exits retain native beforeunload protection.
