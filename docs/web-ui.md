# Web workspace UI

Screen-level behaviour for `apps/web`'s `(workspace)` route group. See `docs/architecture.md` for the app's place in the system.

## Shell and navigation

The sidebar and content layout are adapted from `arda.chat`: a fixed 260 px header inside a sidebar that springs between 260 and 64 px. That JavaScript width spring is the only animated value left; the surrounding content padding, top corner radius, and label opacities are CSS transitions keyed on the shell's state. A single `<Link aria-label="Automator flows">` carries both the mark and the wordmark and stays mounted across states, with the expand control positioned over it when collapsed. Flows, Runs, and Marketplace appear in the main navigation, each with a tooltip when the sidebar is collapsed. The root route (`/`) redirects to `/flows`, the workspace entry page. Sidebar state is restored server-side from a cookie through shared preference-cookie helpers (`apps/web/src/lib/preferences*`); Cmd/Ctrl+Shift+S, registered through a shared hotkey registry (`apps/web/src/lib/hotkeys.ts`), toggles it. A skip link precedes the shell for keyboard users. Reduced-motion preferences disable the layout animations. Links use the shared theme and Remix icons. The workspace shell has no dedicated narrow-viewport mode yet; mobile layout is out of scope for the current milestone.

Each workspace page's title renders as an `<h1>` beside a breadcrumb trail to its parents. Pages render in one of two content modes: the default `document` mode centers and caps page content, while a nested `(canvas)` route group opts a subtree into `fill` mode, which drops padding so the page occupies the full panel. `/flows/[id]` is the canonical flow URL and the first page in `fill` mode; it hosts the flow builder. The workspace route group has shared `loading`, `error`, and `not-found` boundaries.

## Account menu and settings

The bottom account menu opens a responsive Settings dialog with Preferences, Connected apps, Usage, and Account sections. Theme selection works; app connections and usage tracking show unavailable states. Usage limits and reset times are not yet configured or enforced. The tab list is vertical on desktop and horizontally scrollable on mobile, with keyboard navigation and focus restoration to the account trigger. The Account section reads the session directly and shows the profile name, username, and embedded wallet address with a copy-to-clipboard control. Log out clears the web session cookie first and only ends the Privy session once that succeeds. Its Dither Kit avatar is vendored in the shared UI package.

## Flows

Flow creation is available in the Flows header and empty state. Flows (`/flows`) has a responsive empty state with the shared icon illustration and four simple curated flow cards with node icons and integration logos, a short description, Automator attribution, and a Fork flow button; each card opens a `/marketplace/[slug]` detail page. Its presentation component accepts `FlowSummary` records (id, name, description, updated time) from `packages/contracts` and supports labeled grid/table view controls, name search, and sorting; the view preference is restored from a cookie. Flow cards and the flow table show only a name and last-edited date, since the contract carries no status or step outline yet. The page currently supplies an empty list because flow persistence and its API are not implemented.

## Flow builder

`/flows/[id]` renders the builder in the shell's `fill` mode: a toolbar row with breadcrumbs ending in the flow name as an `h1`, a "Local draft" badge that becomes "Unsaved changes" once the graph or meta changes, and a Save control that is `aria-disabled` with a tooltip until the flows API exists. Below it, a 260 px panel is docked on the left, a React Flow canvas fills the middle, and the right side is a 40 px activity rail with a 360 px panel beside it. While the builder is mounted the workspace sidebar is collapsed through a non-persisting override, so leaving the page restores the saved preference.

The canvas draws dummy nodes from the catalog in `apps/web/src/builder/catalog.ts` (four triggers, three integrations, an AI agent, and a screen). Node cards use singular category names (Trigger, Integration, AI, Screen) in the eyebrow, while the palette's category headings use plural form (Triggers, Integrations, etc). Every type declares named ports: triggers have no inputs, USDC payment and the AI agent take two, and every type has at least one output. A card is a header plus a two-column grid of 24 px port rows, one handle per row, and an edge records the port it uses as `sourceHandle` and `targetHandle`. Edges are orthogonal (`smoothstep`). The palette adds a node on click (viewport centre) or drag (pointer position). Connections reject self-loops, duplicates, a second edge into an already-occupied input, and cycles. Delete/Backspace removes the selection, Shift-drag box-selects, and a bottom-left panel zooms and fits the view; a minimap sits bottom-right. An empty canvas shows "Add a node from the palette".

The side panels sit on the card surface, one step above the canvas in both themes. The left panel keeps a flow header at the top: the name, the description clamped to two lines, and a gear that opens the Flow settings dialog, where the name (never committed empty), the description and the live, copyable Flow JSON live. Its body follows the selection: the node palette by default, a "{n} nodes selected." hint above the palette with several nodes selected, and with exactly one node selected that node's settings instead, where a "Back to nodes" control clears the selection and returns to the palette.

The right side is an activity rail of two toggles, AI agent and Screen preview, with the open panel beside it. One panel is open at a time; clicking the open toggle or the panel's collapse control leaves the rail alone on the right, and the choice is not persisted. AI agent is a placeholder chat: an empty state and a composer whose Send is disabled until the AI endpoint exists. Screen preview draws a static phone frame that shows the selected screen node's label, or a hint to select one.

State lives in a per-page zustand store; `serializeFlow` turns it into the `FlowDocument` contract and `hydrateFlow` reverses it. Nothing is persisted yet: reloading discards the flow. `/flows/[id]?example=<slug>` seeds the canvas from a marketplace example as a mini-app trigger followed by one node per step, chained through the first port on each side. React Flow's own colour mode is unused; the builder tokens restyle it in both themes through `flow-builder.module.css`.

## Marketplace

`/marketplace/[slug]` detail pages show a step overview for each curated example; unknown slugs return not-found. The `/marketplace` index itself is an unavailable panel until browsing lands there, so the example cards live on the Flows page instead. Creation and fork links go through `/create`, which mints a flow id and redirects to `/flows/[id]`, forwarding the `example` query parameter so the canvas opens seeded with that example.

## Placeholders and dev tooling

`/runs` and `/marketplace` show a shared unavailable panel (icon, heading, description, and a link back to `/flows`) instead of an empty body, pending feature implementation. There is no dedicated `/settings` route; the Settings dialog is the only entry point. The workspace shell does not fetch API health to render itself. Agentation is available in development only, using the same local annotation setup as UI Lab.
