# Web workspace UI

Screen-level behaviour for `apps/web`'s `(workspace)` and `(canvas)` route groups. See `docs/architecture.md` for the app's place in the system.

## Shell and navigation

The sidebar and content layout are adapted from `arda.chat`: a fixed 260 px header inside a sidebar that springs between 260 and 64 px. That JavaScript width spring is the only animated value left; the surrounding content padding, top corner radius, and label opacities are CSS transitions keyed on the shell's state. A single `<Link aria-label="Automator flows">` carries both the mark and the wordmark and stays mounted across states, with the expand control positioned over it when collapsed. Flows, Runs, and Marketplace appear in the main navigation, each with a tooltip when the sidebar is collapsed. The root route (`/`) redirects to `/flows`, the workspace entry page. Sidebar state is restored server-side from a cookie through shared preference-cookie helpers (`apps/web/src/lib/preferences*`); Cmd/Ctrl+Shift+S, registered through a shared hotkey registry (`apps/web/src/lib/hotkeys.ts`), toggles it. A skip link precedes the shell for keyboard users. Reduced-motion preferences disable the layout animations. Links use the shared theme and Remix icons. The workspace shell has no dedicated narrow-viewport mode yet; mobile layout is out of scope for the current milestone.

Each workspace page's title renders as an `<h1>` beside a breadcrumb trail to its parents; `main` centers and caps page content. The workspace route group has shared `loading`, `error`, and `not-found` boundaries. `/flows/[id]`, the canonical flow URL, lives in the separate `(canvas)` route group, which verifies the session the same way but renders no shell: no sidebar, no header, the builder owns the whole viewport.

## Account menu and settings

The bottom account menu opens a responsive Settings dialog with Preferences, Connected apps, Usage, and Account sections. Theme selection works; app connections and usage tracking show unavailable states. Usage limits and reset times are not yet configured or enforced. The tab list is vertical on desktop and horizontally scrollable on mobile, with keyboard navigation and focus restoration to the account trigger. The Account section reads the session directly and shows the profile name, username, and embedded wallet address with a copy-to-clipboard control. Log out clears the web session cookie first and only ends the Privy session once that succeeds. Its Dither Kit avatar is vendored in the shared UI package.

## Flows

Flow creation is available in the Flows header and empty state. Flows (`/flows`) has a responsive empty state with the shared icon illustration and four simple curated flow cards with node icons and integration logos, a short description, Automator attribution, and a Fork flow button; each card opens a `/marketplace/[slug]` detail page. Its presentation component accepts `FlowSummary` records (id, name, description, updated time) from `packages/contracts` and supports labeled grid/table view controls, name search, and sorting; the view preference is restored from a cookie. Flow cards and the flow table show only a name and last-edited date, since the contract carries no status or step outline yet. The page currently supplies an empty list because flow persistence and its API are not implemented.

## Flow builder

`/flows/[id]` renders the builder edge to edge: a permanent 44 px sidebar on the left edge, a 260 px panel beside it, a middle column with a 44 px header above the React Flow canvas (an outline Simulate button on the left, joined by Stop and Restart icon buttons only while a simulation is running, and a secondary Save button on the right that waits for the flows API), and a 360 px panel docked on the right that minimizes into a 44 px rail on its edge. Every bar shares one rhythm: 44 px of content plus a 1 px border outside it, an 8 px inset, and 28 px ghost icon buttons (Coss `icon-sm`) with 4 px between them, so every control lands on the same pixel row. The panel title rows, the canvas header, the sidebar, and the rail all use it, so the top rows line up and a rail's first control sits on that same row; titles are caption-size medium type. There is no breadcrumb, save control, or draft badge yet; the visual design is being redone from this reduced state.

The canvas draws dummy nodes from the catalog in `apps/web/src/builder/catalog.ts`: 37 types in seven categories (Triggers, Logic, Onchain, AI, Screens, Notifications, Integrations), none with a config schema yet. Type ids are `<kind>.<name>` for core nodes and `<provider>.<name>` for integrations (`world.*`, `privy.*`, `usdc.*`); a provider's trigger, such as `world.verification-completed`, is a trigger by category. Node cards use singular category names in the eyebrow, while the palette's headings use plural form. Every type declares named ports: triggers have no inputs, several types take two, branching types such as If/else have two outputs, and every type has at least one output. A card is a header plus a two-column grid of 24 px port rows, one handle per row, and an edge records the port it uses as `sourceHandle` and `targetHandle`. Edges are orthogonal (`smoothstep`). The palette adds a node on click (viewport centre, through `useAddNodeAtCenter`) or drag (pointer position, through the `application/x-automator-node-type` MIME type). Connections reject self-loops, duplicates, a second edge into an already-occupied input, and cycles. Delete/Backspace removes the selection, Shift-drag box-selects, and a bottom-left panel zooms and fits the view. React Flow's attribution and minimap are hidden.

The side panels sit on the card surface, one step above the canvas in both themes. The sidebar's header slot holds a "Leave flow" icon link back to `/flows` under the same line as every other header. Below it, one ghost icon toggle per panel section (the active one shown pressed) picks what the left panel shows: Nodes (the catalog), Variables (flow inputs, constants and secret references that node configs read), and Outline (a node list with search for large canvases); and a separate "Flow settings" icon button pinned to the bottom has nothing to open yet. The left panel's title row shows the flow name as `h1`, with a small muted flow icon before it. Under Nodes the body is the node palette, a two-level catalog. Its resting state is the group list: a "Core" section with one row per kind (Triggers, Logic, Onchain, AI, Screens, Notifications) and an "Integrations" section with one row per provider (World, Privy, USDC), each row showing an icon or logo, a description, and the node count. Opening a group replaces the list with that group's entries under a "‹ All" back control and the group name; a provider's entries split into Triggers and Actions sections, so a provider's own trigger lives with its actions rather than under Core › Triggers. The search box above (matching labels and descriptions, case-insensitively) wins while it has text and shows flat results sectioned by group across the whole catalog; clearing it returns to wherever the palette was. A grid-view toggle beside the search switches node lists between rows (icon, label, one-line description) and three-per-row tiles (description in a tooltip). No match shows "No nodes match." with a Clear search link. Groups are declared in `catalog.ts` (`catalogGroups`, each entry carries a `group`), and the three views are the pure functions `listCatalogGroups`, `getCatalogGroupSections`, and `searchCatalog`. Search, open group, and view are component state and reset with the page. Variables and Outline are empty until they are designed. The right panel's title row starts with a minimize control, and right-aligned Coss tabs (icon and label, 24 px tall in the 28 px list) switch between AI agent and Screen preview, each an empty tab panel. Minimized, the panel becomes a right rail with one toggle per tab that reopens the panel on that tab. The state is not persisted.

State lives in a per-page zustand store; `serializeFlow` turns it into the `FlowDocument` contract and `hydrateFlow` reverses it. The store also holds a `simulation` status (`idle` or `running`) with `startSimulation` and `stopSimulation` actions that only flip it for now; Simulate disables itself while running, Restart calls start again, and the runner will replace the action bodies. Nothing is persisted yet: reloading discards the flow. `/flows/[id]?example=<slug>` seeds the canvas from a marketplace example as a mini-app trigger followed by one node per step, chained through the first port on each side. React Flow's own colour mode is unused; the builder tokens restyle it in both themes through `flow-builder.module.css`.

## Marketplace

`/marketplace/[slug]` detail pages show a step overview for each curated example; unknown slugs return not-found. The `/marketplace` index itself is an unavailable panel until browsing lands there, so the example cards live on the Flows page instead. Creation and fork links go through `/create`, which mints a flow id and redirects to `/flows/[id]`, forwarding the `example` query parameter so the canvas opens seeded with that example.

## Placeholders and dev tooling

`/runs` and `/marketplace` show a shared unavailable panel (icon, heading, description, and a link back to `/flows`) instead of an empty body, pending feature implementation. There is no dedicated `/settings` route; the Settings dialog is the only entry point. The workspace shell does not fetch API health to render itself. Agentation is available in development only, using the same local annotation setup as UI Lab.
