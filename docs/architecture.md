# Automator Architecture

The repository uses Bun workspaces and Turborepo. Application code is TypeScript with strict checking.

- `apps/web`: Next.js App Router application on port 3000, the dashboard/builder host. The `(workspace)` route group uses the sidebar and content layout adapted from `arda.chat`: a fixed 260 px header inside a sidebar that springs between 260 and 64 px, coordinated content padding and top corner animations, and a shared sidebar provider. The primary-colored logo switches to an expand control on hover or keyboard focus when collapsed. Home, Flows, Runs, and Marketplace appear in the main navigation. The bottom account menu opens Settings in a wide dialog with a working theme preference. Until authentication is integrated, it displays an Account label and a dummy wallet address. Log out is a placeholder action with a callback seam for authentication. Its Dither Kit avatar is vendored in the shared UI package. Agentation is available in development only, using the same local annotation setup as UI Lab. Links use the shared theme and Remix icons. Sidebar state is restored server-side from a cookie; Cmd/Ctrl+Shift+S toggles it. Reduced-motion preferences disable the layout animations. Home (`/`), Create (`/create`), Flows, Runs, Marketplace, and Settings routes exist with intentionally empty page bodies pending feature implementation. It does not fetch API health to render the shell.
- `apps/runtime`: Next.js App Router application on port 3002, the host for shared end-user apps. Currently contains a landing placeholder, error and not-found screens, and a process health endpoint. App rendering and shared-link lookup are not implemented yet. Production uses `PORT` when set, otherwise 3002.
- `apps/ui-lab`: local Next.js component preview on port 3003. A plain app-owned sidebar and header surround previews for the installed UI primitives, with a theme toggle and content width presets. Agentation provides browser annotations in development only, without an Agent Sync server or webhook. It imports shared UI and configuration packages without API or database dependencies. It has no Railway service.
- `apps/api`: Elysia application running on Bun. Uses port 3001 by default, overridable with `PORT`, and listens on IPv6 for Railway private networking.
- `packages/db`: Bun SQL connection pool and database health query (`SELECT 1`). Connections use `DATABASE_URL`; health queries time out after three seconds. No ORM or schema has been selected yet.
- `packages/contracts`: database-independent TypeBox schemas, inferred TypeScript types, endpoint paths, and HTTP response validation. API and web consume the same contracts; the database package imports only its health status type.
- `packages/api-client`: shared server-only HTTP client. Its `./server` export currently provides `getHealth`, with contract validation, uncached requests, a five-second timeout, and tests for unavailable/malformed responses. Callers supply `API_URL`; the package does not read environment variables. The `server-only` marker prevents importing it into a Next.js client component.
- `packages/ui`: shared React primitives sourced from the official Coss UI registry, built on Base UI. Includes buttons, inputs, select, dialog, menu, tabs, tooltip, checkbox, switch, badge, field, textarea, separator, progress, and their supporting components, plus `ThemeProvider` and a Coss-based `ThemeSelect`. The theme provider uses next-themes with system/light/dark selection; all frontend layouts mount it. Components are imported through explicit exports such as `@automator/ui/button` and support both Server and Client Component consumers. The package has no Next.js, API, or database dependency. Coss sources retain their original variants, sizing, typography classes, borders, and interaction styles; Button decorative shadows and inset highlights are removed for a flatter appearance. Our palette is applied through semantic color tokens. Standard Tailwind text sizes coexist with app typography roles, and the Coss radius scale uses a 10 px base. `packages/ui/COSS.md` records provenance and local adaptations. The `apps/ui-lab` application previews shared component variants and surfaces.
- `packages/tailwind-config`: shared Tailwind v4 stylesheet, Inter and Geist Mono variable fonts and licenses, and PostCSS configuration. The imported `colors.css` owns the approved neutral and five-step chromatic palettes plus Coss-compatible semantic color names. Neutral roles invert in dark mode; chromatic scales remain fixed. The imported `typography.css` defines semantic page (30/33), panel (24/29), section (18/24), body (15/23), label (15/21), caption (13/20), and code (13/20) sizes/line heights in pixels at the default root size; values use rem to respect user font preferences. Headings and labels use weight 500; body, captions, and code use 400. Body is the default. Use `text-balance` with headings, `text-pretty` with short descriptions, and cap long-form text at 60–75 characters. Pair `text-code` with `font-mono`; prominent amounts use `font-mono text-body tabular-nums`. Keep full identifiers accessible when wrapping or truncating them. Each frontend, including UI Lab, imports this stylesheet and `@automator/ui/styles.css`, then registers its own source directory. Automatic scanning is disabled, so each app includes only its own and shared UI classes.
- `packages/typescript-config`: strict base, React, and Next.js configurations. Each consumer declares the package as a workspace development dependency and owns its source paths and runtime types.

The data access boundary is `web/runtime → api → db`. Neither frontend depends on `@automator/db`; both use server-side `API_URL` for backend access. The API owns database access, including the database health query; see the API-only access rule in `AGENTS.md`. Editor code belongs in `apps/web`; shared visual primitives belong in `packages/ui`.

Define shared request/response shapes in `packages/contracts` and derive types from their schemas instead of duplicating interfaces. Elysia validates its responses against these schemas. Next.js validates unknown health response JSON against the same schema and HTTP status before consuming it. HTTP 200 requires a healthy database; HTTP 503 requires an unavailable or unconfigured database. Contracts have no dependency on Elysia, database drivers, or database schemas.

Development and production share one Railway PostgreSQL database. Local development uses its public TCP endpoint with TLS; the Railway API uses the private connection URL. Credentials belong in ignored environment files or Railway variables. Copy each app's `.env.example` to `apps/api/.env`, `apps/web/.env.local`, and `apps/runtime/.env.local`, then supply the connection values. Frontend files contain only `API_URL`, never database credentials.

API `/health` returns 200 when the database query succeeds and 503 when the database is unavailable or unconfigured. API `/health/live` and both frontends' `/health` only check their own process. The API client's health result distinguishes a reachable API with a failed database from an unreachable API. There is no authentication or workflow implementation yet.

Each application owns its dependencies, TypeScript configuration, and scripts. Root scripts delegate to Turborepo for development, builds, production startup, type checking, and tests. Build outputs are `.next/` for each frontend and `dist/` for the API. Development and production servers are persistent, uncached tasks. Shared packages export source directly; Next.js compiles the consumed TypeScript packages. Workspace dependencies propagate build/typecheck cache invalidation, and a transit task propagates lint invalidation through shared configuration packages. Frontend build hashes include local environment files and `API_URL`.

Run `bun install` and `bun run dev` from the repository root to start web (3000), API (3001), runtime (3002), and UI Lab (3003). Run one app with `bun run dev --filter=@automator/web` or `bun run dev --filter=@automator/runtime`; start the API separately when needed. Run UI Lab independently with `bun run dev --filter=@automator/ui-lab`; it needs no environment file or backend service. Use `bun run lint`, `bun run typecheck`, `bun run test`, `bun run build`, and `bun run format:check` for verification.

Railway's `automator` project contains `web`, `api`, and `Postgres` in the `production` environment. `.railway/railway.ts` defines service commands, variables, networking, readiness checks, and restart policies. Both app services build from the repository root with a Turbo package filter. The web service is public; it calls the API over Railway's private network. Web and API are connected to GitHub and have successful deployments.

The Railway definition also declares a `runtime` service with an independent build/start command, port 3002, `/health`, and private API access. Provision this service with `railway config apply` and configure a public Railway domain targeting port 3002.

The connected application source is `ardasarico/automator` on GitHub, branch `main`. Deploy applications through GitHub pushes, with each service's watch patterns selecting relevant changes. Do not upload local application files with `railway up`.

Use Railway CLI 5.49.2 or newer to run `railway config plan` and review changes before `railway config apply`. Version 5.42.1 reported an unnecessary Postgres networking update for the same configuration; 5.49.2 correctly limits this plan to creating runtime. Database credentials are kept in Railway, referenced by the API configuration. GitHub pushes deploy application code; changes to `.railway/railway.ts` require a separate config plan/apply.

Oxlint checks application packages and Railway configuration, with React, Next.js, and accessibility rules for all three frontends and React/accessibility rules for shared UI. Imports of the database package and configured database drivers, plus direct `process.env.DATABASE_URL` access, are lint errors in both frontends, UI, API client, and contracts. Oxfmt formats repository sources and configuration; READMEs, licenses, installed skills, and generated files are excluded. The repository requires lint and build to pass before push or deployment.
